# Hinge 2.0.1 preview — page-switch performance

The reported slowdown occurs when switching pages or changing settings.

## Confirmed repeated work

Every return to Effects constructed a new FoldRenderer on the main thread, compiling the Metal library and render/compute pipelines and creating the generated artwork. A local XCTest measured a cold setup at approximately 260 ms. This measures resource setup, not total page-switch time.

## Changes

- Retain the preview renderer and its artwork in AppModel across navigation. Returning to Effects reattaches a new MTKView to the existing resources.
- Invalidate the renderer's previous draw signature on attachment so a new view always receives its first frame.
- Only wake the preview from SwiftUI when its rendering inputs or animation state change. Unrelated status updates and manual-mode sensor readings no longer restart a settled display link.
- Version 2.0.1, build 201. Existing preferences and identity retained.

## Checks

33 tests passed, including a new test that reacquires the preview renderer 100 times, verifies renderer and artwork identity, and confirms current effect/softness values are still reflected. Average cached acquisition was below 0.001 ms on this run; this is not an end-to-end responsiveness benchmark.

First opening still creates the renderer once. Live screen-capture performance and complete UI responsiveness are separate from this measured resource-creation fix. The customer signing/notarization requirements remain unchanged.

Release build and DMG checksum passed. Mounted the DMG read-only and verified the bundled signature and version 2.0.1. Interactive UI verification could not complete: the native inspection service returned timeoutReached.
